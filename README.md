# Local First

[Leia em Portugues](README.pt-BR.md)

## About the project

Local First is a habit tracker built in Rust that runs entirely in the terminal. Its purpose is to help you create, organize, and track your daily habits in a simple and fast way, without requiring an internet connection or cloud account.

The entire project revolves around a single file called habit.json, which is created and updated automatically every time you interact with the program. Your data stays entirely on your computer, ensuring privacy and full control over your information.

The program offers six basic features.

1. Create a new habit by entering only its name.
2. Edit the name of an existing habit.
3. Delete an existing habit.
4. List all habits currently saved.
5. Mark a habit as completed.
6. Exit the program.

Each habit has a unique identifier automatically generated by the UUID system, a name defined by you, and a boolean status indicating whether the habit has been completed or not.


## How to install

To run Local First on your machine, you need to have Rust installed. If you do not have it yet, visit the official website at https://www.rust-lang.org/tools/install and follow the installer instructions for your operating system.

With Rust installed, open the terminal and run the following steps.

First, clone the project repository.

```
git clone https://github.com/elevengr/Local-First
```

Then, enter the project folder.

```
cd Local-First
```

Now compile the project with the build command.

```
cargo build
```

This process will download all dependencies and generate the executable inside the target/debug folder.


## How to run

To start the program, run the command below inside the project folder.

```
cargo run
```

The main menu will appear in the terminal with the six available options. Simply type the number corresponding to the action you want to perform and press enter.

On the first run, the habit.json file is automatically created at the project root. All future operations of creation, editing, deletion, listing, and completion update this file directly.


## Usage examples

**Creating a habit**

When selecting option 1, the program asks for the habit name. You type the name and the habit is saved immediately.

```
Selectd option: 1
Name: 
Learn Rust
```

After this action, the habit is recorded in the habit.json file with a unique identifier, the name you provided, and an initial status of false.

**Listing habits**

When selecting option 4, all saved habits are displayed in the terminal in formatted JSON, making it easy to view.

**Editing a habit**

When selecting option 2, the program asks for the identifier of the habit you want to change and then the new name. The record is updated in the file.

**Deleting a habit**

When selecting option 3, you provide the identifier of the habit and it is permanently removed from the list.

**Completing a habit**

When selecting option 5, you provide the identifier of the habit and its status is changed to true (completed). If the habit does not exist, an error message is displayed.

**Exiting the program**

When selecting option 6, the program terminates.


## How the project works internally

The program is written in a single source file, located at src/main.rs. It uses the tokio library as an async runtime, although all input and output operations are executed synchronously in the terminal.

Data is persisted in JSON format. With each operation, the program reads the content of the habit.json file, loads the habit list into memory, performs the requested action, and saves the updated list back to the file.

Each habit structure contains three fields: a UUID v4 as a unique identifier, a string with the habit name, and a boolean value for the status. JSON serialization and deserialization are handled by the serde and serde_json libraries.


## Project dependencies

The project uses the following Rust libraries.

1. tokio, for the async runtime.
2. uuid, for unique identifier generation with version 4 support and JSON serialization.
3. serde, for automatic serialization and deserialization derivation.
4. serde_json, for reading and writing in JSON format.


## Important notes

The habit.json file is the only persistence file in the project and should not be modified manually, as direct changes may compromise data integrity.

The project is in its early stages of development and uses Rust edition 2024. Contributions and improvements are welcome.
